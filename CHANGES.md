# Changes

## Unreleased

- `Workero.tail` and `Workero.Trace`: Tail Workers. `tail` registers the handler (`Trace.t list -> Env.t -> Context.t -> unit`); `Trace` reads a trace item with `outcome`, `event` (`Fetch`, `Scheduled`, `Queue` or `Other`), `event_timestamp`, `script_name`, `logs`, `exceptions`, `truncated`, `wall_time`, `cpu_time` and `to_js`, and `Trace.Request` gives the redacted request and `unredacted`. `workero build` exports `tail` only when the program registers it. Streaming tails are not supported.
- `Workero.Abort_controller` and `Workero.Abort_signal` wrap `AbortController` and `AbortSignal`: `create`, `signal`, `abort ?reason` (`` `Abort msg `` or `` `Timeout msg ``), `aborted`, `reason`, `throw_if_aborted`, `timeout`, `any`, `aborted_now`, `on_abort` (runs in its own fiber), `to_promise`, `is_abort`. `?signal` on `Workero.fetch`, `Fetcher.fetch` and `Fetcher.fetch_request` cancels the request and the reading of its body. `Request.signal` is the signal of the incoming request. It needs the `enable_request_signal` compatibility flag, which the template `wrangler.toml` now sets. An abort cancels the I/O, not the fiber; see `doc/abort.mld`.
- `Workero.Html_rewriter`: the runtime `HTMLRewriter`. `create`, `on ?element ?text ?comments selector`, `on_document ?doctype ?text ?comments ?end_` and `transform` rewrite a response while it streams. Selectors are strings; content is `Text` (escaped) or `Html`. The node modules `Element`, `End_tag`, `Text_chunk`, `Comment`, `Doctype` and `Document_end` wrap the runtime objects. Handlers run as fibers and may await.
- The `workero` CLI uses Cmdliner. `workero --help`, `workero build --help` and `workero package --help` describe the commands. Usage errors print the usage line and exit with code 1. An unexpected exception, such as a file-system error, exits with code 125. When `--out` is given more than once, the last one wins. `cmdliner` is a new dependency.
- Faster requests: a response without headers makes no `Headers` object, a handler that does not suspend makes no extra Promise, and `URL.path` decodes only paths that contain `%`.
- `Workero.Workflow`: Cloudflare Workflows. `register name run` (the event has the `workflow_name` and the cron `schedule`) binds a `WorkflowEntrypoint` class written in OCaml; `run env event step` uses `Step.do_ ?retries ?timeout ?rollback` (the callback gets a `Step.context` with the attempt number, the step name and count, and the retry configuration; `Step.retries_with` computes each retry delay from a function; `Step.rollback` undoes a step), `Step.sleep`, `Step.sleep_until` and `Step.wait_for_event` (it returns the event: type, payload and timestamp) with `Rpc.value` results (the structured-clone types: also `Undefined`, `Bytes`, `Date`, `Bigint`, `Map` and `Set`), `Duration` and `Non_retryable`. The binding side has `of_env`, `create ?retention`, `create_batch`, `create_batch_count`, `delete_batch`, `get` and `Instance` (`id`, `status`, `pause`, `resume`, `terminate ?rollback`, `restart ?from`, `delete`, `send_event`). `workero build` exports the class and writes `workflow.js` only when a Workflow is registered. `workerd` has no Workflows engine, so the tests use a JavaScript engine that calls the class over RPC; see `doc/known_issues.mld`.
- `Durable_object.Storage.transaction` and `rollback`: an asynchronous transaction (JavaScript `ctx.storage.transaction`) whose function may call `Promise.await`. An exception rolls back the storage and SQL writes and reaches the caller; `rollback` undoes them without raising.
- `Workero.Rpc`: one value type for RPC. `Rpc.t` holds the JSON constructors and also `Undefined`, `Bytes`, `Date`, `Bigint`, `Map`, `Set`, `Stream`, `Stub` and `Function`, in both directions. `Durable_object.make ?rpc`, `Durable_object.call`, `Entrypoint.make ?rpc` and `Entrypoint.call` use it instead of `Jsonkit.t` (`Rpc.of_json` and `Rpc.to_json` convert); a JavaScript `undefined` result now reads as `` `Undefined `` instead of `` `Null ``.
- `Rpc.value` and `Rpc.to_value`: the structured-clone subset of `Rpc.t` (no `Stream`, `Stub` or `Function`), the values that Workflows persist. A `value` converts to `Rpc.t` with `(v :> Rpc.t)`; `to_value` converts back and raises `Invalid_argument` on `Stream`, `Stub` or `Function` at any depth.
- RPC methods on Durable Object stubs: `Durable_object.register ~rpc:["incr"]` declares method names, `make ~rpc` answers calls with JSON arguments and results, and `Durable_object.call stub name args` calls a method from OCaml. JavaScript calls `stub.incr()`. `workero build` adds the declared methods to the exported class; the class manifest now carries a kind and method names for each class.
- `Workero.Entrypoint`: `WorkerEntrypoint` classes with RPC methods. `register ?rpc` binds a class and its method names, `make ?fetch ?rpc` builds the handlers (JSON arguments and results, the `rpc` handler gets the method name like `Durable_object.make`), and `call` calls an RPC method of a service binding from OCaml. `workero build` exports every registered entrypoint from `index.js` and writes `entrypoint.js`. The probe in `workerd` reports the entrypoints with their methods, and the build fails when an entrypoint and a Durable Object class share a name.
- `Workero.Crypto` covers `crypto.subtle`: digests, HMAC, AES-GCM, AES-CBC, AES-CTR, AES-KW, RSASSA-PKCS1-v1_5, RSA-PSS, RSA-OAEP, ECDSA (P-256, P-384, P-521), ECDH, Ed25519, X25519, PBKDF2 and HKDF. `Key.generate`, `Key.generate_pair`, `Key.import` (`raw`, `jwk`, `spki`, `pkcs8`) and `Key.export_*` make and read extractable keys; `wrap_key` and `unwrap_key` wrap keys with AES-KW, AES-GCM or RSA-OAEP; `Digest_stream` hashes a stream. Keys are typed by algorithm, and asymmetric keys by `Key.public` or `Key.private_`, so a signing function does not accept an HMAC key or a public key. Bytes are OCaml strings; a JWK is its JSON text. `Key.import_hmac` and `Key.import_aes_gcm` keep their types and make non-extractable keys.
- `Workero.Socket`: outbound TCP sockets (`connect` from `cloudflare:sockets`) with `connect ~host ~port` (`?secure_transport` of `Off | On | Starttls`, `?allow_half_open`), `opened` (waits, gives `info` with the remote and local address), `closed`, `reader`, `writer`, `close` and `start_tls`. `index.js` now always imports `cloudflare:sockets`.
- `Stream.Reader.release`, `Stream.Writer.release` and `Stream.Writer.of_js`.
- `Workero.Email` and `Workero.email`: the Email Routing handler. `Email.t` has `from`, `to_`, `header`, `header_all`, `headers`, `raw_size`, `raw` (a `Stream.t`), `raw_text`, `raw_bytes`, `set_reject`, `forward ?headers` and `reply`, which takes the raw message as `` `Text of string `` or `` `Stream of Stream.t ``. `workero build` exports `email` only when the program registers it. `index.js` loads `cloudflare:email` when `reply` is called, so `workerd` runs the handler but cannot run `reply`.
- `Durable_object.State.container` and `Durable_object.Container` (`running`, `start`, `monitor`, `destroy`, `signal`, `get_tcp_port`): Cloudflare Containers attached to a Durable Object. `get_tcp_port` gives a `Fetcher.t`. `Container.connect ~port` gives a `Socket.t` for raw TCP, `set_inactivity_timeout ~ms`, and `intercept_outbound_http`, `intercept_all_outbound_http` and `intercept_outbound_https` send the outbound requests of the container to a `Fetcher.t`.
- `Workero.Queue`: Cloudflare Queues. Producer: `of_env`, `send`, `send_batch`, `message` with a `Json | Text | Bytes` body and `?delay_seconds`. Consumer: `Message` (`id`, `timestamp`, `attempts`, `body_json`, `body_text`, `body_bytes`, `body_js`, `ack`, `retry`) and `Batch` (`queue`, `messages`, `ack_all`, `retry_all`). Under `open Workero`, `Queue` hides `Stdlib.Queue`.
- `Workero.queue` registers the queue consumer. `workero build` exports `queue` only when the program registers it.
- `Workero.Hyperdrive` (`of_env`, `connection_string`, `host`, `port`, `user`, `password`, `database`): the connection details of a Hyperdrive binding. It has no query driver.
- `Workero.Rate_limiter` (`limit`), `Workero.Ai` (`run`, `run_bytes`) and `Workero.Analytics_engine` (`write`).
- `Workero.Durable_object`: Durable Objects with SQLite storage. `register` binds a class, `make` builds its handlers (`init`, `fetch`, `alarm`), `Namespace` opens a binding and gives stubs (a `Fetcher.t`), `Id`, `State` and `Storage` (synchronous key-value, alarms, `sync`, `delete_all`).
- `Durable_object.Sql` (`query`, `run`, `database_size`) with `Storage.sql`, `Storage.transaction_sync` (rolls back and re-raises the original exception; `Promise.await` inside raises `Invalid_argument`), and hibernatable WebSockets: `make ~websocket_message ~websocket_close ~websocket_error`, `State.accept_websocket`, `websockets`, `tags`, `set_websocket_auto_response`, and `Websocket.serialize_attachment` / `deserialize_attachment`.
- `workero build` and `workero package` run the program once in `workerd` to read the registered Durable Object classes, export them from `index.js` and write `durable-object.js`. They need `workerd` (`WORKERD`, `PATH` or `node_modules/.bin`). A program that raises during initialisation now fails the build with its error.
- `index.js` accepts a worker that registers only Durable Object classes.
- `Env.secret` reads a required string variable or secret and raises `Invalid_argument`, without the value, when it is missing or not a string. `Env.json` reads an object or array variable as a `Jsonkit.t`.
- `JSON.of_js` and `JSON.to_js` convert between JavaScript values and `Jsonkit.t` through `JSON.stringify` and `JSON.parse`.
- `Workero.Secret_store`: Secrets Store secrets (`of_env`, `get`).
- `Workero.Fetcher`: service bindings and assets (`of_env`, `fetch`, `fetch_request`), the type that Durable Object stubs use.
- `Workero.Router`: routes with `get`, `post` and the other methods, `any`, `scope`, `wrap`, `make`, `find` and `to_handler`. Patterns follow the server-reason-react route syntax: `/users/:id<int>`, `/files/:rest<string...>`. Static beats parameter beats catch-all; `make` rejects duplicate and ambiguous routes. `to_handler` answers 400, 404, 405 with `Allow`, and a 308 for trailing slashes.
- `URL.pathname`, `URL.search`, `URL.hash` and `URL.origin` give the raw parts of a URL, as the JavaScript `URL` does.
- `Context.pass_through_on_exception` binds `ctx.passThroughOnException()`. It needs a route with an origin.
- `serve` and `scheduled` flush standard output and standard error when a handler ends, also when it raises, so `print_string` and `Printf.printf` reach the logs without `%!`. Output from a `wait_until` function that runs after the handler returns appears when the next handler ends.
- First release: the `workero` library and the `workero build` CLI.
  - `Workero.serve` (HTTP handler with `Request`, `Env`, `Context`) and `Workero.scheduled` (Cron Triggers). `workero build` exports only the registered handlers.
  - `Workero.fetch` for outgoing requests, `Context.wait_until`, `Promise.await` in direct style.
  - `Request`: `method_` (`Method.t`), `url` (`URL.t`), `header`, `headers`, `text`, `bytes`, `cf`.
  - `Response`: `text`, `html`, `make`, `redirect`, and `status`, `header`, `headers`, `body_text`, `body_bytes`.
  - `to_js` and `of_js` on each type.
- `Workero.JSON`: JSON requests and responses. Values are `Jsonkit.t`. The module has no `t` alias and does not re-export jsonkit; add `jsonkit` to your dune `libraries`.
- Storage bindings: `Workero.KV` (`list` follows the cursor), `Workero.Cache`, `Workero.R2`, `Workero.D1` with `Workero.Sql_value` (`Int of int64`, exact up to 2^53). JS errors in bindings, thrown or rejected, raise `Js_error "Name: message"`.
- `Workero.Promise` is backed by `Js_of_ocaml.Promise`, so `'a t t` is sound. `of_js` and binding calls take a decoder (`Workero.Decode`). `Promise.error` is opaque and `Js_error` carries the original JS reason. New `map`, `bind`, `all`, `race`, `any`, `all_settled`.
- An exception during program initialisation fails the worker load with its message, instead of "registered no handler".
- `workero build` fails when the program uses functions with no wasm implementation, instead of failing on each request.
- Typed bindings for JavaScript globals: `Workero.Timer` (`sleep`, `set_timeout`, `set_interval`, `clear_timeout`, `clear_interval`), `Workero.Date`, `Workero.Crypto` and `Workero.Console`. Examples and tests no longer call `setTimeout` through `Js.Unsafe`.
- Naming: `Sql_value.row`, one `__workero` JS global, `Decode.unit`, `Makefile` targets `test-worker-init` and `test-worker-exports`.
- `Workero.Stream`: byte streams with `Reader`, `Writer`, `iter` and `pipe`. `Request.body` and `Response.body` give a stream. `Response.stream` writes a body in its own fiber with back-pressure, and a client disconnect raises `Js_error` on write. `Response.of_stream` passes a body through.
- `Workero.Form_data` and `Request.form_data`: multipart and urlencoded forms, with text values and files (`file_name`, `file_type`, `file_size`, `file_bytes`, `file_stream`). The runtime buffers the whole upload.
- `Workero.Websocket`: `upgrade` with a receive loop, `pair`, `accept`, `send`, `receive`, `close`, `response`. Events come in order; there are no callbacks.
- New `Request` values: `path`, `query_string`, `header_all`, `clone`, `body`.
- New `Response` values: `empty`, `copy`, `clone`, `header_all`, `body`, `of_stream`, `stream`.
- `Response.redirect` accepts a relative URL, such as `"/login"`.
- Breaking: `~status` is a `Workero.Status` variant, not an `int`: ``Response.text ~status:`Not_Found``, ``Response.empty `No_Content``. Tags follow Dream; ``Status n`` names any other code. ``Response.redirect`` takes only the redirect tags. A no-body status with a body does not type-check; ``Status 204`` with a body, or a code outside 200..599, raises `Invalid_argument`. `Response.status` still returns an `int`.
- `URL` uses the JavaScript `URL`. A host with `_` and a URL with userinfo now parse, and `Request.url` does not raise for them. `?a` gives `("a", "")`. `+` in a path stays `+`. A malformed escape such as `%zz` leaves the whole path undecoded. `to_string` gives the normalised `href`: a trailing `/` is added and the fragment is kept.
