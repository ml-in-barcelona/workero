
# R2

Store and retrieve object bytes with [`Workero.R2`](./Workero-R2.md), a buffered subset of [Cloudflare R2](https://developers.cloudflare.com/r2/). The bytes of an object fit in an OCaml `string`. `R2.get` reads the whole object into Worker memory; use this API only for objects that fit that limit.


## Configure the binding

For local development, add this to `wrangler.toml`. `opam exec -- wrangler dev` creates local storage:

```toml
[[r2_buckets]]
binding = "BUCKET"
```

## Write the Worker

```ocaml
let handler req env _ctx =
  let open Workero in
  let bucket = R2.of_env env "BUCKET" in
  let key = URL.path (Request.url req) in
  match Request.method_ req with
  | PUT ->
      R2.put ?content_type:(Request.header req "content-type") bucket key
        (Request.bytes req);
      Response.text ~status:`Created "stored\n"
  | GET -> (
      match R2.get bucket key with
      | Some bytes -> Response.make ~headers:[ ("content-type", "text/plain") ] bytes
      | None -> Response.text ~status:`Not_Found "not found\n")
  | DELETE ->
      R2.delete bucket key;
      Response.text "deleted\n"
  | _ -> Response.text ~status:`Method_Not_Allowed "method not allowed\n"

let () = Workero.serve handler
```
The example returns text for the local check. For other bytes, choose a response `content-type` that fits the object. `R2.put` can store the supplied `content_type` as object metadata. `R2.head` reads `size`, `etag` and optional `content_type` without reading the body. `R2.head` and `R2.get` are separate requests, not an atomic metadata-and-body read. Either can observe a change between the calls. `R2.get` and `R2.head` return `None` for a missing key; `R2.delete` accepts one. See [`Workero.R2`](./Workero-R2.md) for the API.


## Verify locally

Run `opam exec -- wrangler dev` in one terminal. In a second terminal:

```sh
curl -X PUT -H "content-type: text/plain" -d hello http://localhost:8787/notes.txt
curl http://localhost:8787/notes.txt
```
The responses are `stored` (status 201\), then `hello` (status 200\).


## Deploy with an existing bucket

Remote creation requires an authenticated Wrangler. If you do not let [Wrangler provision it on deploy](https://developers.cloudflare.com/workers/wrangler/configuration/#automatic-provisioning), create a bucket and set its name in `wrangler.toml`:

```sh
opam exec -- wrangler r2 bucket create my-bucket
```
```toml
[[r2_buckets]]
binding = "BUCKET"
bucket_name = "my-bucket"
```
See [Cloudflare R2 setup](https://developers.cloudflare.com/r2/get-started/) and [R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/). See [Getting started](./getting_started.md) for deployment steps.
