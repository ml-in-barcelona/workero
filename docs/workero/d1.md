
# D1

Run basic SQL queries with [`Workero.D1`](./Workero-D1.md), a subset of the [Cloudflare D1](https://developers.cloudflare.com/d1/) API. D1 stores a SQLite database.


## Configure the binding and schema

For local development, put this in `wrangler.toml`:

```toml
[[d1_databases]]
binding = "DB"
```
Create the local table before you send requests. `--local` writes to the same local D1 storage that `opam exec -- wrangler dev` uses:

```sh
opam exec -- wrangler d1 execute DB --local \
  --command "CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, name TEXT)"
```

## Write the Worker

```ocaml
let handler req env _ctx =
  let open Workero in
  let db = D1.of_env env "DB" in
  match (Request.method_ req, URL.path (Request.url req)) with
  | POST, "/users" ->
      let name = Request.text req in
      let changed =
        D1.run db "INSERT INTO users (name) VALUES (?)" ~params:[ D1.Text name ]
      in
      Response.text (Printf.sprintf "inserted %d row\n" changed)
  | GET, "/users" ->
      let rows = D1.query db "SELECT id, name FROM users ORDER BY id" in
      let names =
        List.filter_map
          (fun row ->
            match List.assoc_opt "name" row with
            | Some (D1.Text name) -> Some name
            | _ -> None)
          rows
      in
      Response.text (String.concat "\n" names ^ "\n")
  | _ -> Response.text ~status:`Not_Found "not found\n"

let () = Workero.serve handler
```
`D1.run` executes a statement that returns no rows and gives the number of changed rows. `D1.query` returns rows as lists of `(column, value)` pairs in result order. Bind user input to SQL `?` marks with `~params`; do not join it into SQL text. An SQL error raises [`Workero.Js_error`](./Workero.md#exception-Js_error). Use [`Workero.Promise.error_to_string`](./Workero-Promise.md#val-error_to_string) to read the underlying error.


## Verify locally

Run `opam exec -- wrangler dev` in one terminal. In a second terminal:

```sh
curl -X POST -d ada http://localhost:8787/users
curl http://localhost:8787/users
```
The responses are `inserted 1 row` and `ada`. The local database persists between runs of `wrangler dev`.


## Deploy with an existing database

Remote creation requires an authenticated Wrangler. If you do not let [Wrangler provision it on deploy](https://developers.cloudflare.com/workers/wrangler/configuration/#automatic-provisioning), create a database and copy the printed ID into `wrangler.toml`:

```sh
opam exec -- wrangler d1 create my-database
```
```toml
[[d1_databases]]
binding = "DB"
database_name = "my-database"
database_id = "<database id>"
```
Create the table in the remote database before sending requests to the deployed Worker. If Wrangler provisions the database on deploy, deploy first, then create the table:

```sh
opam exec -- wrangler d1 execute DB --remote \
  --command "CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, name TEXT)"
```
For later schema changes, use [D1 migrations](https://developers.cloudflare.com/d1/reference/migrations/). `--local` and `--remote` write to different databases. See [Getting started](./getting_started.md) for deployment steps.


## SQL values

[`Workero.Sql_value.t`](./Workero-Sql_value.md#type-t) (also [`Workero.D1.value`](./Workero-D1.md#type-value)) represents a column or parameter:

- `Null`
- `Int of int64`
- `Float of float`
- `Text of string`
- `Blob of string`, raw bytes

### Numeric precision

D1 carries numbers as JavaScript numbers. `Int` parameters must be within ±`2^53`; [`Workero.Sql_value.to_js`](./Workero-Sql_value.md#val-to_js) raises `Invalid_argument` outside that range before SQL runs.

A read cannot distinguish an `INTEGER` column from a `REAL` column. Numbers without a fractional part within ±`2^53` read as `Int`, so a `REAL` value of `2.0` reads as `Int 2L`. Other numbers read as `Float`. An `INTEGER` beyond `2^53` reaches OCaml already rounded by the runtime, not as an exact `int64`. See [`Workero.Sql_value`](./Workero-Sql_value.md) and the [Cloudflare D1 Worker API](https://developers.cloudflare.com/d1/worker-api/).
