
# D1

[`Workero.D1`](./Workero-D1.md) is a [Cloudflare D1](https://developers.cloudflare.com/d1/) database: SQLite on Cloudflare.


## Configure

```sh
npx wrangler d1 create my-database
```
Copy the printed values into `wrangler.toml`:

```toml
[[d1_databases]]
binding = "DB"
database_name = "my-database"
database_id = "<database id>"
```
Create the tables with a migration or `wrangler d1 execute`. For local development, add `--local`:

```sh
npx wrangler d1 execute my-database --local \
  --command "CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT)"
```

## Use

```ocaml
let handler req env _ctx =
  let open Workero in
  let db = D1.of_env env "DB" in
  match (Request.method_ req, URL.path (Request.url req)) with
  | POST, "/users" ->
      let name = Request.text req in
      let changed =
        D1.run db "INSERT INTO users (name) VALUES (?)" ~params:[ Text name ]
      in
      Response.text (Printf.sprintf "inserted %d row\n" changed)
  | GET, "/users" ->
      let rows = D1.query db "SELECT id, name FROM users ORDER BY id" in
      let names =
        List.filter_map
          (fun row ->
            match List.assoc_opt "name" row with
            | Some (D1.Text name) -> Some name
            | _ -> None)
          rows
      in
      Response.text (String.concat "\n" names ^ "\n")
  | _ -> Response.text ~status:404 "not found\n"

let () = Workero.serve handler
```
- [`Workero.D1.of_env`](./Workero-D1.md#val-of_env) opens the database bound as `"DB"`. It raises `Invalid_argument` when there is no such binding.
- [`Workero.D1.query`](./Workero-D1.md#val-query) runs SQL and gives the rows. Each row is a list of `(column, value)` pairs in result order.
- [`Workero.D1.run`](./Workero-D1.md#val-run) runs a statement that returns no rows, such as `INSERT` or `CREATE TABLE`, and gives the number of rows that it changed.
- `~params` are values for the `?` marks of the SQL, in order. Always pass user input as parameters. Never build SQL by joining strings.
An SQL error raises [`Workero.Js_error`](./Workero.md#exception-Js_error). Read the message of the database with [`Workero.Promise.error_to_string`](./Workero-Promise.md#val-error_to_string).


## SQL values

[`Workero.Sql_value.t`](./Workero-Sql_value.md#type-t) (also [`Workero.D1.value`](./Workero-D1.md#type-value)) is the value of one column:

- `Null`
- `Int of int64`
- `Float of float`
- `Text of string`
- `Blob of string`, raw bytes
```ocaml
let show (value : Workero.Sql_value.t) =
  match value with
  | Null -> "null"
  | Int n -> Int64.to_string n
  | Float f -> string_of_float f
  | Text s -> s
  | Blob b -> Printf.sprintf "%d bytes" (String.length b)

let () =
  Workero.serve (fun _req env _ctx ->
      let db = Workero.D1.of_env env "DB" in
      let rows =
        Workero.D1.query db "SELECT ?, ?, ?, ?, ?"
          ~params:[ Int 42L; Float 1.5; Text "hi"; Blob "\000\255"; Null ]
      in
      let cells = List.concat_map (List.map (fun (_, v) -> show v)) rows in
      Workero.Response.text (String.concat ", " cells ^ "\n"))
```
D1 carries numbers as JavaScript numbers, which are 64-bit floats:

- An `Int` is exact only within ±253. [`Workero.Sql_value.to_js`](./Workero-Sql_value.md#val-to_js) raises `Invalid_argument` for an `Int` beyond that, so the call fails before any SQL runs.
- A column that holds `1.0` cannot be told apart from `1`. Both read as `Int 1L`.
- A `Float` is read only for a number with a fractional part, or beyond 253.

## Test locally

`wrangler dev` uses a local D1 database. Run the commands of *Configure* with `--local`, then:

```sh
npx wrangler dev
curl -X POST -d ada localhost:8787/users
curl localhost:8787/users
```
